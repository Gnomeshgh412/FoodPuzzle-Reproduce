## 3. 第一性原理与文献依据

### 3.1 MFP

当前 MFP train 的 567 个具体食物与 dev 的 71 个具体食物交集为 0。封闭训练食物检索无法恢复 dev 具体实体，所以当前最大瓶颈位于 Scientist 候选召回，不是 Reviewer 选择。

FoodPuzzle 原文将 Scientific Agent 描述为 Scientist 提出三个假设、Reviewer 选择或拒绝，并强调通用 LLM 缺乏食品科学领域知识；原文同时将搜索空间初始化列为最大错误项。原文：<https://arxiv.org/html/2409.12832>。

GENRE 将实体检索表述为生成有意义的实体名称，说明生成式名称空间可以突破封闭原子标签分类；但该论文也明确指出无约束生成可能产生无效实体，并使用约束解码解决。因此本轮只开放一个具体食物槽位，保留两个冻结 BM25 候选和无效响应安全回退，而没有把整个候选空间交给自由生成。原始论文：<https://arxiv.org/abs/2010.00904>。

文献提供设计原则，不保证 FoodPuzzle 小样本必然提升，也不证明通用模型参数中拥有足够的分子—食物知识。

### 3.2 MPC

FoodPuzzle 的 MPC 输出是 exact-N 具体分子，但主指标是预测/Gold 分子集合的官能团 F1。原文：<https://arxiv.org/html/2409.12832>。

Waegeman 等指出，F-measure 是结构化、多标签任务中的非分解目标，以其他损失作为替代可能产生较大 regret。这支持把“数据库对称官能团代理”与正式非对称 F1 明确分开。原始论文：<https://www.jmlr.org/papers/v15/waegeman14a.html>。

Cawley 与 Talbot 指出，在有限验证样本上反复选择模型会过拟合选择准则并产生性能评估偏差。因此本轮只建立当前 H1 control，看到结果后没有自适应加入第二个模块。原始论文：<https://www.jmlr.org/papers/v11/cawley10a.html>。

## 4. 冻结方案

### 4.1 MFP 唯一变化

- 保留冻结 BM25 前两名；
- 将原 BM25 第三名替换为一次 DeepSeek 开放生成的具体食物；
- 固定系统要求：输出可实际指认的具体食物，不得输出宏类别、不得复制两个类比食品、不得声称输入未提供的实验事实，只返回 JSON；
- 固定响应键：`开放具体食物`、`支持分子`、`冲突`；
- 支持分子只能来自输入分子；
- 无效或缺失响应回退原 BM25 第三名；
- Reviewer、UniMol、证据桥、排序、正式评测冻结。

预注册硬门：

1. 有效响应率至少 95%；
2. 具体食物 Top3 召回改善的配对 bootstrap 95% 下界大于 0；
3. 冻结 FlavorDB 映射下，宏类别 Top3 oracle 均值不下降。

若具体食物仍为零恢复，停止继续微调同一开放提示词。

### 4.2 MPC 唯一动作

- 用 568 条 MPC train 拟合当前 masked-query pairwise occurrence ranker；
- 在 71 条 MPC dev 生成 `proposal_occurrence`，不使用 `proposal_metric_aligned` 或任何后续动作；
- 强制 exact-N、无重复、排除 partial；
- 本地报告具体分子 P/R/F1 与数据库对称官能团 F1；
- 预测冻结后，使用现有官方评测器将预测分子经 DeepSeek 映射到固定 53 项官能团词表，Gold 官能团来自 FlavorDB；
- 独立 cache，不读取或覆盖正式 cache；
- 唯一分子数超过 500 时在 API 前停止。

本轮 MPC 的完成条件是得到可信 control，不是获得方法增益。

## 7. MPC control 结果

### 7.1 调用前完整性与本地指标

- 71/71 exact-N；
- 无缺失、额外或解析失败预测；
- 唯一预测分子：465，小于 500 上限；
- 具体分子 precision/recall/F1：`0.6941170158`；exact-N 下三者相同；
- 数据库对称官能团 F1：`0.9126148536`。

### 7.2 官方非对称指标

- 官方官能团 precision：`0.5933664013`；
- 官方官能团 recall：`0.7501151779`；
- 官方官能团 F1：`0.6490999554`；
- zero-F1 样本：0；
- Gold 数据库查询失败：0；
- 预测分子数量不等于 N：0。

当前 H1 dev 官方 F1 与历史 v12 正式 test F1 `0.65386721` 数值接近，但二者属于不同 split、不同执行对象，不能据此宣布持平、提升或退化。

### 7.3 代理—官方口径差距

同一批冻结预测上：

- 官方 F1 − 数据库对称 F1：`-0.2635148981`；
- 配对 bootstrap 95% 区间：`[-0.2898192338, -0.2389014248]`；
- 具体分子 F1 与官方官能团 F1 的样本相关：`0.3835`；
- 数据库官能团 F1 与官方官能团 F1 的样本相关：`0.6501`；
- 每个预测集合的 LLM 映射与数据库映射之间，平均集合 F1 只有 `0.6701`；
- 数据库预测官能团平均种类数 `19.87`，LLM 映射平均 `23.24`。

因此数据库对称 F1 可作为有噪声诊断，但不能再当成官方 F1 的数值替代或单独准入依据。

### 7.4 空映射不是主因

- 23 个唯一分子得到空官能团集合，跨样本出现 196 次；
- 含空映射的 64 个样本平均官方 F1 为 `0.6628`；
- 不含空映射的 7 个样本平均官方 F1 为 `0.5235`。

所以不能把主差距简单归因于“Reviewer/评测器不知道 23 个分子”。空集合同时包含“模型无法判断”和“固定词表中无合适组”，现有 cache 不足以再细分。

### 7.5 官方口径固有限制

模型侧 `parse_official_functional_groups` 与评测侧 `parse_functional_groups` 行为一致，并非两份本地代码不一致。它们都逐字复现公开的空格切分行为，因此 Gold 会出现预测固定词表无法输出的碎片：

- `compound`：71 个样本；
- `or`：56 个样本；
- `(sulfanyl`：41 个样本；
- `(trialkylamine)`：3 个样本。

Gold 每个样本平均包含 17.17 个官方词表可表达官能团和 2.41 个不可表达碎片。即使完全命中所有可表达 Gold 且无额外预测，仅由这些碎片导致的逐样本理论 F1 上限均值约为 `0.9334`。

该限制必须如实披露，不能私改正式评测去获得更高分。

### 7.6 当前最大可行动瓶颈

官方 precision `0.5934` 明显低于 recall `0.7501`。高频假阳性包括：

- `sulfanyl` 63；
- `ether` 52；
- `thioether` 50；
- `chloride` 47；
- `oxo(het)arene` 45；
- `halide` / `halogen` 各 44；
- `cation` / `hydroxyhetarene` 各 43。

当前 occurrence H1 高频重复选择会扩大官能团并集的分子，例如：`methanethiol` 52 次、`vanillin` 46 次、`3-methylthiopropanol` 46 次、`3-(Methylthio)propionaldehyde` 45 次、`thiamine` 44 次、`kaempferol` 43 次。`thiamine` 的一次 LLM 映射包含 18 个官能团，对 precision 风险尤其大。

因此当前更清晰的 MPC 瓶颈仍在 **Scientist H1 如何给出与查询需求匹配、不过度扩大官能团并集的具体分子集合**，不是 Reviewer 如何从现有候选中选择。过去 v14/v15 的数据库代理双门未通过，而本轮证明该代理与官方口径还有系统性差距，不能继续沿原代理阈值微调。
