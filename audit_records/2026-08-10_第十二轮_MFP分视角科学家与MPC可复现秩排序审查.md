# 第十二轮：MFP 分视角 Scientist 与 MPC 可复现秩排序审查

日期：2026-08-10  
结论：MFP 未通过并停止；MPC 训练 OOF 未通过探索准入，按冻结方案不读 dev Gold。

## 一、授权、边界与准入政策修正

用户在听取本轮双任务瓶颈、历史信号、唯一方向和停止条件后明确允许执行。MFP 和 MPC 保持独立：

- MFP 只改 Scientist 候选组织方式，Reviewer 、Prompt、证据和评测器冻结；
- MPC 只重建不依赖漂移主版本的候选效用排序；
- 不读正式 test，不用任务外 FlavorDB 数据作为方法输入，不新增数据、文献证据集或中间模型；
- raw FlavorDB 仅由既有 MFP 官方类别评测器使用，没有回流给 Scientist/Reviewer；
- 不覆盖历史产物，不修改正式主版本，不执行 Git 写操作。

本轮之前专门复查了“是否准入过严”。结论是：过去把五个固定分块当作五个独立数据集，或用 `wins ≥ 2×losses` 作为探索阶段硬门槛，确实可能过严；但第九至十一轮的部分零/负结果不是被严格统计条件“误杀”。因此从本轮起区分：

1. **直接拒绝**：主点估计非正、阶段机制指标恶化、具体输出严重崩溃、泄漏或不可复现；
2. **探索保留**：主点估计与阶段机制均为正，具体输出安全，wins>losses；95% CI 和固定分块如实报告但不单独否决；
3. **论文主方法冻结**：仍需严格的独立证据、95% CI 或一次性正式测试。

Card et al. (EMNLP 2020) 指出 NLP 比较常因测试集过小而统计功效不足；Dror et al. (ACL 2018) 强调显著性检验必须匹配指标与数据假设。这些文献支持报告不确定性，但不支持忽略方向性负结果。

## 二、MFP

### 2.1 历史信号、瓶颈与第一性原理

当前 K=3 完整 Agent 在 71 条 dev 上：

- Scientist Top3 宏类别 oracle：`41/71 = 0.577465`；
- Reviewer 宏类别 accuracy：`25/71 = 0.352113`；
- 46 条 Reviewer 错误中，30 条是 Scientist 三候选缺失正确类别，16 条是 Reviewer 选择失败。

因此最大瓶颈仍在 Scientist 候选缺失，不是 Reviewer。历史上：

- 第三轮的候选多样性在 train OOF 上有 `+0.029982` 正增益和正的 95% 下界，但因当时“4/5 分块非负”硬门槛被拒绝；
- 第十一轮将 Top3 检索直接扩大到 Top10，Scientist oracle 和 Reviewer 均零增益。

从任务生成机制看，单次调用要在同一上下文中产生三个互补具体食物，容易受首个高显著性模式支配。新方法应当新增“候选间差异化”归纳偏置，而不是新增数据。

Multiple Choice Learning（NeurIPS 2012）支持直接关注 best-of-K 候选集损失；RAG（NeurIPS 2020）支持在生成前使用非参数训练记忆。两者都不能保证“多调用”自然等于“多样性”。

### 2.2 冻结方法

唯一改动：将 BM25 Top9 按排名固定拆成 `(1,4,7)/(2,5,8)/(3,6,9)` 三个不重叠视角，三次独立 Scientist 调用各取第 1 个具体食物，组成三候选。

冻结 Scientist/Reviewer Prompt、DeepSeek `deepseek-v4-flash`、answer-masked 官方证据、5 个起始分子、每分子 3 条证据、Reviewer 使用的原 Top3 demonstrations 和评测器。输出始终为具体食物，不给 Scientist/Reviewer 宏类别。

探索保留要求 Scientist oracle 和 Reviewer 主指标都高于 K3，wins>losses，71/71 成功且无直接宏类别输出；CI 和五分块只报告。

### 2.3 执行完整性

- train/dev ID 无重叠，71/71 均有 9 个检索训练示例；
- 官方证据 SHA256：`42428e09c5c0ba3eda39b5e3efbe83aebe568f473d86b9ec5b3ba03ef577292b`；
- 首次调用出现 1 条 `IncompleteRead`，主遍历又有 2 条 SSL EOF；全部原样重试成功，失败记录不进入方法评价；
- 71/71 最终 Scientist 三分支和 Reviewer 解析成功；屏蔽后证据中实际食物命中数为 0；
- 四路官方类别映射均为 71/71，无 mapping failure；
- Reviewer 直接输出宏类别数为 0。

### 2.4 结果

| 指标 | K=3 对照 | 分视角 | 增益 |
|---|---:|---:|---:|
| Scientist 第1候选宏类别 accuracy | 0.352113 | 0.366197 | +0.014085 |
| Scientist 第2候选宏类别 accuracy | 0.239437 | 0.253521 | +0.014085 |
| Scientist 第3候选宏类别 accuracy | 0.352113 | 0.323944 | -0.028169 |
| Scientist Top3 宏类别 oracle | **0.577465** | **0.422535** | **-0.154930** |
| Reviewer 宏类别 accuracy | **0.352113** | **0.338028** | **-0.014085** |

- Scientist oracle 增益 paired bootstrap 95% CI：`[-0.253521, -0.070423]`；
- Reviewer 增益 95% CI：`[-0.070423, +0.042254]`，`2 wins / 3 losses / 66 ties`；
- Reviewer 五个固定分块增益：`-0.066667 / -0.071429 / +0.071429 / +0.071429 / -0.071429`；
- 本轮 Scientist oracle 只有 30 条，Reviewer 正确 24 条，选择损失 6 条；
- Scientist Top1/Top3 具体食物命中 `0/2`，Reviewer 具体食物命中 `1`；
- 三候选平均只有 `1.8592` 个不同具体食物，**34/71** 样本的三个候选完全相同。

### 2.5 结论

**未通过并停止。**

本轮证明：将相邻检索支持硬拆成三组并进行多次调用，并没有产生历史第三轮所需的“候选多样性”。三个分支仍被相同分子和证据中的高显著食物主导，导致 34 条完全重复。

不继续调整 `(1,4,7)` 等分组，不增加调用数挽救。历史上“多样性有信号”仍可保留为研究线索，但下一方法必须新增真实的候选间差异化约束，不能再把“多调用”当作“多样性”。

## 三、MPC

### 3.1 历史信号、瓶颈与第一性原理

- 第九轮表明食品条件 ICL 核心可提供与 H1 互补的具体分子；
- 第十轮共识锚定候选效用排序在 train OOF 上有稳定正信号；
- 第十一轮证明第十轮源码丢失且执行器动态加载的当前主版本已漂移，不能在不可复现基线上继续门控。

MPC 必须在 exact-N 下同时决定“加入谁”和“移除谁”。候选召回充足不等于可安全交换。Recall-then-Verify（ACL 2022）支持把候选召回与验证分开；RankNet/成对排序支持直接学习候选相对效用。它们不能保证简化的秩特征会同时保护大分子集合。

### 3.2 冻结方法

仅使用已冻结 H1 和 ICL 列表的：

- `1/H1 rank`；
- `1/ICL rank`；
- H1/ICL 共识指示。

在既有 exact-profile 5-fold 上做外折 OOF，用其余折 Gold 构造查询平衡的正负成对差分，固定 `LogisticRegression(C=1, fit_intercept=False, solver=liblinear)`。共识候选优先保留，其余按分数填满 exact-N。

训练探索准入预注册为：macro 与 micro 具体分子 F1 都高于 H1，wins>losses，至少 3/5 折非负，最差折不低于 `-0.01`，568/568 exact-N。任一失败即不读 dev Gold。

### 3.3 实施口径修正

首次预检使用的分子归一化只处理大小写和空格，导致 H1 macro 与历史口径相差约 `0.00035`。在正式审计前主动发现该问题：

- 不覆盖预检产物；
- 仅将归一化修正为仓库既有 MPC 口径：小写化，连字符/下划线转空格，移除非英文数字标点，合并空格；
- 在新目录完整重跑，没有改特征、折、模型、参数、门槛或候选。

修正后 H1 macro/micro 精确对齐历史值 `0.6649148489 / 0.7756545203`，正式审查使用修正后结果。

### 3.4 训练 OOF 结果

| 指标 | H1 | 新秩排序 | 增益 |
|---|---:|---:|---:|
| macro 具体分子 F1 | 0.664915 | 0.678413 | **+0.013498** |
| micro 具体分子 F1 | 0.775655 | 0.773468 | **-0.002187** |

- macro 增益 bootstrap 95% CI：`[+0.006449, +0.020851]`；
- 五折 macro 增益：`+0.002483 / +0.024444 / +0.011166 / +0.009597 / +0.019823`；
- `116 wins / 145 losses / 307 ties`；
- 568/568 exact-N；
- 训练 OOF 未通过：**micro 下降且 wins<losses**。

### 3.5 结论

**未通过探索准入，按预注册停止，未读 dev Gold，未运行官能团评测。**

这不是“95% CI 或五分块过严”造成的误杀：本轮的 CI 和五折反而都支持 macro 改善。真正问题是 macro 改善集中在较小的查询，而大分子集合中的损失使 micro 下降，且受损查询数多于受益查询数。简化秩特征能识别一部分高置信候选，但不足以保护 exact-N 下被移除的 H1 分子。

不在本轮调整 macro/micro 权重、共识锁定规则、阈值或排序特征挽救。

## 四、本轮对历史学习规则的落实

从本轮起，每轮“现状核验”必须新增一项显式检查：

1. 找出与当前瓶颈直接相关的历史成功、局部信号和失败；
2. 分开“机制信号”和“历史具体实现”，只取可验证的机制，不直接将旧版本认定为最优；
3. 审查新方法是否真正实现了历史信号所对应的归纳偏置；
4. 对历史失败建立“不得简单重复”的停止边界。

本轮对这条规则的直接证据是：MFP 借鉴了第三轮的多样性信号，但实验证明“多次调用”不等于真多样性；MPC 借鉴第九/十轮的候选互补与共识信号，但证明仅靠秩与共识不能解决安全移除。
