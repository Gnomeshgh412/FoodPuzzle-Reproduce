# MPC 正式口径收益上限分解审计

> **部分更正（2026-08-01）**：Top-20 Bank Oracle `+0.04595` 与原始 Top-5 Oracle `+0.02813` 是事后上限分析，仍然有效；但本文中的“结构执行器”使用 held-out Gold 选择动作，不是合法推理策略。其收益、Oracle 捕获率以及基于该分数的后续排序建议已撤销。无泄漏结构 posterior 重算见 `2026-08-01_mpc-structure-route-leakage-correction-and-legal-audit.md`。

## 1. 审计问题

冻结结构执行器虽然取得正收益，但约 `+0.0169` 仍不足以支撑预期的 MPC 突破。本轮不再修改方法，而是定位剩余收益丢失在哪一段：

1. H1 到 Top-20 Action Bank 的动作空间是否有足够上限；
2. Top-20 压缩到 Scientist Top-5 时损失多少；
3. Top-5 已包含正确动作时，结构执行器又损失多少；
4. 当前单交换路线是否还值得继续。

本轮未修改代码、未调用 API、未覆盖正式结果。官能团规则、H1、Action Bank 和 Scientist Top-5 均保持冻结；评测 cache 只用于动作确定后的只读 Oracle 分解。

## 2. 覆盖范围

| 指标 | 结果 |
|---|---:|
| 全部训练查询 | 568 |
| H1 cache 完整覆盖 | 511 |
| 可完成执行器与 Oracle 分解 | 510 |
| Top-5 动作 cache 覆盖率 | 99.29% |
| Top-20 动作 cache 覆盖率 | 99.55% |
| Top-5 全动作完整查询 | 503 |
| Top-20 全动作完整查询 | 502 |

动作覆盖率接近 100%，因此在 H1 已覆盖的 511 条内，Bank 与 Top-5 Oracle 的低估幅度很小；主要限制仍是另外 57 个 H1 未被历史 cache 覆盖。

## 3. 三阶段收益上限

在相同的 510 个可分解查询上：

| 阶段 | 正式口径平均 F1 增益 | bootstrap 95% 下界 | 正收益查询 |
|---|---:|---:|---:|
| Top-20 Bank Oracle | **+0.04594515** | **+0.03987301** | 188 |
| Scientist Top-5 Oracle | **+0.02813141** | **+0.02381472** | 155 |
| 冻结结构执行器（保守 tie-break） | **+0.01662388** | +0.01320875* | 104 |

`*` 结构执行器下界来自上一轮 511 条主审计；本轮上限分解的重点是 Oracle 差值。

这给出明确结论：

- Top-20 Bank 的单交换空间具有约 `+0.046` 的正式口径上限，足以支撑明显改善；
- Scientist 压缩到 Top-5 后，上限下降到约 `+0.028`，已经低于我们希望达到的约 `+0.03`；
- 当前结构执行器进一步只实现约 `+0.0166`。

因此，“单交换没有潜力”不是当前结论；真正问题是有价值动作没有稳定通过 `Bank → Top-5 → Executor` 两层压缩。

## 4. 损失分解

采用此前已运行、较保守的并列分数处理结果：

| 损失位置 | 平均 F1 损失 | 占 Bank Oracle 上限 |
|---|---:|---:|
| Top-20 Bank → Scientist Top-5 | **0.01781375** | **38.77%** |
| Scientist Top-5 → 结构执行器 | 0.01150752 | 25.05% |
| Bank → 最终结构执行器总损失 | 0.02932127 | 63.82% |

当前结构执行器捕获：

- Top-5 Oracle 的 59.09%；
- Top-20 Bank Oracle 的 36.18%。

因此当前最大的单段瓶颈已经不是结构官能团表示，而是 **Scientist 对 Action Bank 的 Top-5 排序/压缩**。

## 5. 查询类型分解

在本轮一次性、较早 rank 优先的 tie-break 诊断中，查询分布为：

| 类型 | 查询数 |
|---|---:|
| Top-20 Bank 没有正式正动作 | 322 |
| Bank 有正动作，但 Top-5 完全漏掉 | 33 |
| Top-5 有正动作，但执行器未获得正收益 | 44 |
| 执行器等于 Top-5 Oracle | 99 |
| 执行器为正，但低于 Top-5 Oracle | 12 |

这说明存在两个不同问题：

1. 33 条查询是纯粹的 Top-5 召回失败；
2. 44 条查询是 Top-5 已经含正动作，但选择/拒绝仍失败。

从查询数看两者接近；从宏 F1 损失量看，Bank→Top-5 的损失更大。

## 6. Tie-break 敏感性

本轮发现结构 `ΔF1` 完全相同时，选择较早还是较晚的 Scientist rank 会改变结果：

| 并列策略 | 平均正式增益 | 负收益查询 | 捕获 Top-5 Oracle |
|---|---:|---:|---:|
| 较晚 rank 优先（上一轮实际审计） | +0.01662388 | 16 | 59.09% |
| 较早 rank 优先（本轮诊断） | +0.02090497 | 7 | 74.31% |

由于此前没有预注册 tie-break，不能在看到结果后采用表现更好的“较早 rank 优先”并将它当作新收益。本审计采用较低的上一轮结果作为主结论。

这也揭示结构代理的剩余局限：多个 proposal 可以形成相同官能团集合，但正式 LLM evaluator 对具体分子名称的官能团输出并不完全相同。仅靠集合级结构 `ΔF1` 无法区分这些动作。

下一阶段必须预先冻结 tie-break，或在结构并列时 `KEEP_H1`；不能根据当前 cache 选择有利规则。

## 8. 对“收益不够”的直接回答

用户的判断成立：`+0.0166～+0.0169` 不足以作为最终 MPC 创新收益。

但本轮也排除了两个悲观解释：

- 不是 UniMol 缺失导致 MPC 无法提高；
- 不是单交换 Action Bank 没有足够上限。

Top-20 Bank Oracle 的 `+0.04595` 表明，当前候选空间已有足够潜力。主要损失发生在 Top-5 排序，其次是 Top-5 内的执行选择。现在直接实现现有结构执行器，只会固化一个尚未充分利用候选空间的版本。

## 9. 下一步唯一合理动作

下一轮只审计 **结构对齐的 Scientist Bank→Top-5 重排序**，不接入正式 Agent：

1. 保持 Top-20 Bank 不变；
2. 保持冻结结构官能团规则不变；
3. 不读取 cache；
4. 将 Scientist 的候选压缩改为一个预注册的、多目标且通用的排序：
   - 原有 food-conditioned expected-F1 作为相关性 prior；
   - 冻结结构 `ΔF1` 作为 metric-aligned utility；
   - 对完全相同的 proposal 官能团集合去重；
   - 保留 add/remove 官能团方向的候选多样性，避免 Top-5 全部表达同一种交换；
5. 只检查新的 Top-5 Oracle 是否显著接近 Top-20 Oracle；
6. 此阶段先不优化 Executor，避免同时修改两段；
7. 目标至少将 Top-5 Oracle 从 `+0.02813` 提升到 `>= +0.038`，即捕获至少约 82.7% 的 Bank Oracle；
8. 未达到则停止 Top-5 压缩路线，考虑让 Reviewer 直接审查更大的 Bank，而不是继续调权重。

`+0.038` 是根据当前 Bank Oracle 预先设置的机制准入线，不是正式测试集调参目标。cache 只能在排序冻结后作一次性 Oracle 评估。

## 10. 当前路线决策

- 暂不接入现有结构执行器到正式 Agent；
- 不进行 API 运行；
- 保留冻结结构官能团感知层；
- 下一瓶颈：Scientist Bank→Top-5 排序；
- 不扩大 Action Bank，不引入 UniMol，不增加 Agent 层；
- 下一轮只做 Top-5 重排序离线审计，必须再次获得用户批准。
