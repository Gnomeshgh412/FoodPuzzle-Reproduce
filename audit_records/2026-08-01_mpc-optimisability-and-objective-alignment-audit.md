# MPC 可优化性与目标对齐审计

## 审计范围

本轮不设计或实现新版本，只回答三个问题：

1. 当前离线代理目标是否足够接近正式 MPC 评测；
2. 不使用评测缓存的合法通用特征是否包含可学习信号；
3. 官方离线 evidence 是否足以验证 Scientist 提出的具体交换动作。

本轮未修改正式代码、未调用 API、未覆盖任何正式结果。评测缓存只作为一次性的只读诊断 Oracle，绝不作为模型输入、训练特征或推理资源。

## 结论先行

连续多个版本没有稳定改善，并不主要说明“还缺一个更复杂的 Reviewer”，而是说明优化闭环的反馈信号发生了系统性错位：

- 离线优化用 FlavorDB 字符串解析得到的官能团同时表示 Gold 和候选分子；
- 正式评测只对 Gold 使用该数据库解析，而对预测分子使用 LLM 在固定词表中重新抽取官能团；
- 因此离线动作收益与正式动作收益不是同一个目标。

在 2,105 个 Scientist Top-5 原子交换动作上，两种收益的 Pearson 相关系数仅为 `0.382006`。被本地代理判为正收益的动作中，只有 `47.99%` 在正式口径诊断下仍为正收益。此前约 `+0.005` 到 `+0.008` 的离线改善，远小于表示错位造成的约 `+0.11` 到 `+0.24` 的方法级 F1 虚高，因而很容易在正式评测中消失甚至反转。

与此同时，合法通用动作特征对“正式正收益动作”仍有明显区分能力：诊断性五折 OOF ROC-AUC 为 `0.822702`、PR-AUC 为 `0.432605`，而正例率只有 `0.202375`。这说明问题不是完全没有可学习信号，而是过去主要用错误的代理标签训练和选择门控器。

所以，在建立与正式语义相容、且不依赖评测缓存的官能团表示之前，不应继续命名或实现 v16，也不应继续堆叠 Scientist、Reviewer、Fusion Agent 或阈值。

## 1. 正式评测与离线代理的定义差异

当前正式兼容评测流程具有不对称性：

- Gold missing molecules：从 FlavorDB 的 `molecules.functional_groups` 读取并按公开评测逻辑解析；
- Predicted molecules：由 LLM 根据固定官能团词表抽取，并写入共享 functional-group cache；
- 最终指标：对这两个来源形成的官能团并集计算 precision、recall、F1 与 IoU。

而 v13–v15 的离线动作校准对 Gold 与预测候选都使用 FlavorDB 解析结果。它测量的是 `DB(prediction) vs DB(gold)`，不是正式评测的 `LLM(prediction) vs DB(gold)`。

这不是一个小的实现细节。FlavorDB 原始字段包含多词标签和 `@` 标记，公开兼容解析器先按空格切分，只对部分 token 做特殊处理，可能产生 `compound`、`acid`、`or` 等碎片；LLM cache 则倾向输出固定词表中的 `alkene`、`aryl`、`ether` 等化学类别。二者的标签空间和粒度并不等价。

## 2. 分子级表示一致性

共享评测 cache 与 FlavorDB 的只读比较结果如下：

| 指标 | 结果 |
|---|---:|
| cache 原始条目 | 2,910 |
| cache 归一化唯一分子 | 2,875 |
| 与数据库共同覆盖的分子 | 1,141 |
| 官能团集合完全一致 | 93 / 1,141（8.15%） |
| 平均 Jaccard | 0.348690 |
| 中位 Jaccard | 0.333333 |
| Jaccard < 0.5 | 821 / 1,141 |

在查询级 Gold 官能团并集上，两种表示也仍有明显差异：

| 划分 | cache 分子覆盖率 | 并集平均 Jaccard | 中位 Jaccard | Jaccard < 0.5 |
|---|---:|---:|---:|---:|
| 训练 568 条 | 96.786% | 0.593470 | 0.636364 | 103 / 568 |
| 测试 71 条 | 96.559% | 0.556180 | 0.620690 | 20 / 71 |

这说明即便 cache 对常见分子覆盖较高，集合语义也没有与 DB 代理自然对齐。

## 3. 方法级代理虚高

对现有预测文件进行只读重算，得到以下比较。`正式 F1` 是现存正式 summary；`DB 对称代理 F1` 对预测与 Gold 均使用数据库官能团；`重构混合 F1` 使用 cache 表示预测、数据库表示 Gold。重构值与正式值的微小差异来自快速诊断中的名称归一化细节，因此只用于判断方向和量级。

| 方法 | 正式 F1 | DB 对称代理 F1 | 重构混合 F1 | 代理相对重构虚高 |
|---|---:|---:|---:|---:|
| Zero-shot | 0.535463 | 0.645740 | 0.533320 | +0.112420 |
| Scientist–Reviewer Agent | 0.601222 | 0.774580 | 0.597124 | +0.177455 |
| ICL | 0.675761 | 0.906160 | 0.669789 | +0.236370 |
| Multi-Agent | 0.656526 | 0.866432 | 0.652042 | +0.214390 |
| 当前 Optimized-Agent | 0.653867 | 0.857793 | 0.649468 | +0.208325 |

方法的大体排序没有完全颠倒，但代理的绝对尺度严重乐观。过去离线优化只移动几个千分点，而代理误差是其数十倍，因此不能依据该代理决定新模块是否值得进入正式运行。

## 4. 动作级错位：直接解释历次失败

在固定 `PYTHONHASHSEED=0`、按完整谱聚类的五折 OOF 设置下，共审计 568 个查询、2,105 个 Scientist Top-5 原子交换动作：

| 指标 | 结果 |
|---|---:|
| proxy gain 与 formal-audit gain 的 Pearson 相关 | 0.382006 |
| proxy 判为正的动作 | 546 |
| 其中 formal-audit 也为正 | 262（47.99%） |
| formal-audit 正动作总数 | 426 |
| formal-audit 正例率 | 20.24% |

完整符号混淆矩阵：

| Proxy \\ Formal-audit | 负 | 正 | 平 |
|---|---:|---:|---:|
| 负 | 316 | 121 | 589 |
| 正 | 104 | 262 | 180 |
| 平 | 44 | 43 | 446 |

这意味着一个在 DB 对称代理上“加入正确官能团且安全删除”的动作，在正式口径下未必仍然增加同一组官能团。v15 的 Add Necessity / Remove Safety 分解本身并非毫无道理，但它用 DB proxy 产生监督标签，因此优化的是错误版本的 necessity 和 safety。

## 5. 合法特征是否还有希望

为区分“目标错位”和“特征根本没有信息”，本轮只作诊断性实验：

- 标签：cache 只读重构的 formal-audit 正收益标签；
- 特征：不含 cache，只包含可合法部署的通用信号，如 add/remove 账本、检索支持、H1 边界和集合覆盖；
- 评估：低容量分类器的 stacked 五折 OOF。

结果：

| 指标 | 结果 |
|---|---:|
| ROC-AUC | 0.822702 |
| PR-AUC | 0.432605 |
| 正例率基线 | 0.202375 |

因此，现有合法特征并非完全不可用。真正的问题是：我们没有合法且对齐的训练目标。这个诊断不授权使用 cache 训练未来模型；cache 属于评测过程的一部分，且对 Scientist 新候选覆盖不完整，将其用于模型选择会造成 evaluator leakage 和指标投机。

此外，本结果不能被解释为泛化性能保证。相同训练 OOF 已被 v13–v15 多轮自适应查看，存在 researcher overfitting；下一阶段必须先冻结一个未用于规则设计的开发子集和准入协议。

## 6. 官方离线 evidence 的可实现上限

训练集 568 个查询都有文本片段，但当前项目链接器只有 110 个查询（19.37%）包含至少一个直接分子 occurrence 链接，共 175 次直接链接。关系片段分布为：

| relation | 数量 |
|---|---:|
| ambiguous | 4,604 |
| occurrence support | 490 |
| sensory replication support | 429 |
| functional role support | 150 |
| contradiction | 5 |

进一步对实际 Top-5 additions 作严格检查：要求 occurrence-support 片段直接点名待加入分子，命中的动作数为 `0`，查询覆盖也为 `0`。因此，在当前离线 evidence 与严格名称链接规则下，它不能担任 Top-5 动作的主 verifier。

这里的零命中不是对所有可能别名解析器的数学上界。更完善的实体链接可能恢复少量覆盖，但即使采用项目现有更宽松链接器，查询级直接链接覆盖也只有 19.37%。合理定位是：离线 evidence 可作高精度、低覆盖的附加信号，不能解释或验证大多数交换动作。

## 7. 第一性原理解释

MPC 的决策对象是大小固定的分子集合，而正式损失定义在另一层表示——预测分子的 LLM 官能团并集——上。一个交换动作的真实效用为：

`ΔF1 = F1(LLM-FG(H1 - remove + add), DB-FG(gold)) - F1(LLM-FG(H1), DB-FG(gold))`

我们此前实际优化的是：

`ΔProxy = F1(DB-FG(H1 - remove + add), DB-FG(gold)) - F1(DB-FG(H1), DB-FG(gold))`

只有当 `DB-FG(candidate)` 与 `LLM-FG(candidate)` 足够一致时，后式才是前式的可靠代理。实测分子级完全一致率 8.15%、动作收益相关 0.382，关键前提不成立。继续提高 Reviewer 复杂度，只会更精确地优化错误目标。

这与目标错位文献中的一般结论一致：优化一个代理并不能保证下游目标改善，尤其当二者相关性较弱时。F-measure 本身还是非分解集合指标，逐标签或局部代理可能产生很高的 worst-case regret，不能将单个 add/remove 局部正确性简单等同于最终集合 F1。

## 8. 文献与方法支撑

### 8.1 代理目标必须与下游目标对齐

Lambert et al. 在 L4DC 2020 将“优化一个目标并希望另一个弱相关目标同步改善”明确归纳为 objective mismatch，并展示训练指标改善未必带来下游任务改善。这里的具体领域不同，但逻辑完全对应当前 `DB 对称代理 → 正式混合 F1` 的断裂。

<https://proceedings.mlr.press/v120/lambert20a.html>

Waegeman et al. 在 JMLR 2014 从决策论分析 F-measure，证明使用 Hamming loss、subset 0–1 loss 等代理可能产生很高的最坏情形 regret，并给出直接面向 F-measure 的 Bayes-optimal 方法。它支持我们的停止条件：不能再把容易计算的局部代理当作最终 F1 的等价目标。

<https://www.jmlr.org/papers/v15/waegeman14a.html>

### 8.2 从分子结构确定官能团是通用、可复核的化学信息学路线

Ertl 在 Journal of Cheminformatics 2017 提出从分子图按规则自动识别官能团的算法，并在 ChEMBL 上提取出大量官能团。这说明由 SMILES / 分子图获得官能团不是针对 FoodPuzzle 测试集的启发式，而是独立的通用化学信息学任务。

<https://doi.org/10.1186/s13321-017-0225-z>

RDKit 官方接口提供基于 SMARTS 的官能团层级、分子指纹和子结构匹配能力，可作为未来构造固定、可解释官能团本体的工程基础。

- <https://www.rdkit.org/docs/source/rdkit.Chem.FunctionalGroups.html>
- <https://www.rdkit.org/docs/Cookbook.html#functional-group-with-smarts-queries>

但是，结构识别只能解决“候选分子包含什么官能团”，不能告诉我们“某食物缺的就是哪些分子”，也不能天然复现 LLM evaluator 的标签偏好。因此它是目标对齐候选，不是已经证明有效的 MPC 优化模块，更不是恢复 UniMol 的理由。

## 9. 数据与工程可行性

FlavorDB `molecules` 表的 1,781 个分子均有非空 `smile` 与 `inchi` 字段，因此可以在未来独立构造结构官能团表示。当前项目 Python 环境没有安装 RDKit，本轮没有安装依赖，也没有生成新的结构文件。

UniMol 不应重新进入 MPC 主线：它编码连续三维分子表征，适合 MFP 的分子身份/性质判别；当前 MPC 瓶颈却是离散官能团本体与正式评测语义的对齐。若未来保留 UniMol，也只能作为独立的组合合理性证据，并需单独证明增量收益，不能替代官能团识别。

## 10. 下一阶段的唯一前置问题

下一步不是直接实现 v16，而是先审计一个**冻结的通用官能团感知层**能否作为合法代理：

1. 从外部化学定义预先冻结 SMARTS / 图规则及标签映射，不依据 71 条测试集或 cache 反复调规则；
2. 对所有候选统一从 SMILES 生成官能团表示，禁止 Gold/Prediction 使用两套内部代理；
3. 仅将 cache 用作一次性的审计参照，检查结构表示是否显著提高动作收益相关性，不能把 cache 标签用于训练；
4. 预先冻结未参与规则设计的开发子集、阈值和一次性准入标准；
5. 若动作相关性不能明显高于 `0.382`、proxy-positive 的正式正收益率不能明显高于 `47.99%`，立即停止该方向；
6. 只有通过目标对齐审计，才讨论把它接入 Scientist–Reviewer，而不是同时再加 Agent 层。

需要特别承认：如果一个完全外部冻结的结构本体仍无法接近正式 LLM evaluator，那么剩余差异来自评测器本身的语义随机性/非对称性。在不能使用评测 cache、不能恢复逐候选 LLM 官能团抽取的约束下，这部分可能构成不可消除的可辨识性上限。此时正确结论应是停止 MPC 代理优化，而不是继续发布 v17、v18。

## 11. 路线决策

- 暂停新版本编号和正式 API 运行。
- 不继续调 v14/v15 的门控阈值或增加分类器容量。
- 不增加同源 Reviewer、Fusion Agent 或 Multi-Agent 层。
- 不把评测 cache 用作训练数据或推理特征。
- 不让 UniMol回到 MPC 主优化链。
- 下一项工作只允许是“冻结结构官能团感知层的目标对齐审计”；是否实施必须另行获得用户批准。
