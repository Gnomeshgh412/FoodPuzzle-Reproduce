# MFP PFGA 任务合规验证与候选生成瓶颈审查

日期：2026-08-15

## 审计结论

原 PFGA 在按具体食物选择、只在预测后映射宏类别的任务合规协议下未通过。它相对 identity 仍有局部正信号，但相对使用完全相同信息的简单加权融合平均为 `-0.00291`，且所有训练侧检索方法的具体食物 accuracy 为 0。原先的主要正收益依赖按宏类别聚合，只能作为类别可分性上限，不能作为 MFP 可部署方法。

冻结 dev 上，简单加权为 `0.36620`，PFGA 与后续 QCEA 均为 `0.35211`。QCEA 的 OOF 改善未跨 split 复现，不准入。

历史第十二轮全部 Scientist 候选平均每条 5.65 个，宏类别 oracle 为 `0.67606`，具体食物 oracle 仅为 `3/71`。因而 MFP 新的唯一主瓶颈冻结为：

> 开放具体食物候选生成，以及候选食物—查询分子 `contains` 关系归因。

## MPC 本轮独立对照

POM demand/supply 冻结 OOF 复核结果与旧产物哈希一致。加入 demand/supply 特征时 macro 有局部点收益，但 micro F1 由 `0.77565` 降到 `0.76805–0.76937`；demand-only 为明显负收益。因此不将 POM demand 加入 MPC，继续保留已通过官方近似功能团审查的 P4 作安全父基线。

## 冻结决定

- PFGA-min/product：未通过并停止。
- POM + 官能团加权融合：仅保留为信息通道局部正信号。
- QCEA：冻结 dev 反转，未通过。
- 异构网页片段共现/规则验证：未通过。
- 新方法候选：ECCA（Evidence-Constrained Candidate Attribution）。
- 下一阶段必须先证明 exact-food candidate recall 改善，再证明 relation verifier 能在固定候选上带来 exact-food net wins，最后才能接入 Reviewer。
- 真实 PubMed 检索和 Scientist API 调用需要单独的外部 API/数据传输授权。
