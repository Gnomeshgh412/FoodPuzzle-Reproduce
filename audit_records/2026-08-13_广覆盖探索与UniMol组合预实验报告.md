# 广覆盖探索与 UniMol 组合预实验报告

- 日期：2026-08-13
- 阶段：探索阶段，不是正式结论
- 代码基准：`code/Only-Deepseek/scientific_agent.py`
- 探索目标：从原始 Scientist Agent 出发，广泛寻找能引起正向收益的机制，并确定下一阶段应冻结验证的组合
- 仓库改动：本轮只新增本报告；没有修改 Agent、评估器、数据、split 或既有结果
- 临时实现：全部位于 `/tmp`，未写入仓库
- API：本轮新增预实验没有调用 LLM API；LLM 相关判断使用既有探索结果
- 正式测试：没有读取逐样本答案，没有运行或选择正式 test

## 1. 本轮定位

本轮不是对单一方法做论文级确认，而是进行广覆盖机制发现。允许：

- 在 train OOF、leave-one-out 和已经复用过的 dev 上广泛筛选；
- 同时观察总体增益、候选 oracle、样本互补、失败模式和路由可能性；
- 对出现信号的模块做组合搜索；
- 暂时搜索少量权重、预算、正则强度和 gate 阈值。

仍保持的官方一致性底线：

- 输入以当前近似复现 Scientist Agent 的任务字段为准；
- 不向方法提供当前样本 Gold；
- MFP 输出必须是具体食物；
- MPC 输出必须是具体分子，并由确定性执行器保证去重、排除 partial 和 exact-N；
- 原始 FlavorDB 类别/完整食品画像/官能团不得作为推理侧方法输入；
- 官方近似评估只用于结果度量，不反向进入推理特征。

## 2. 第一性原理假设

### 2.1 MFP

MFP 当前主要瓶颈首先是候选召回，其次才是候选选择。冻结 UniMol 可以描述输入分子结构，但不能凭空知道开放食物实体。因此优先测试三个角色：

1. 直接结构集合最近邻；
2. BM25 候选的结构重排或融合；
3. 与 BM25 正交的异质候选召回专家。

### 2.2 MPC

UniMol 描述候选分子的结构“供给”，不能独立恢复某一食品的分子“需求”。因此测试顺序是：

1. raw H1+ICL 大候选池上的条件相似度；
2. 已经过候选效用模型压缩的边界候选池；
3. exact-N 交换预算；
4. UniMol proposal 之后的选择性 gate。

UniMol 原论文表明它是通用 3D 分子表示，而不是食品—分子共现模型；下游语义仍需任务适配。3D-MoLM 也使用专门的 Q-Former 做结构—语言对齐，而不是直接把冻结余弦当作语义答案：

- Uni-Mol（ICLR 2023）：https://openreview.net/forum?id=6K2RM6wVqKu
- 3D-MoLM（ICLR 2024）：https://openreview.net/forum?id=xI4yNlkaqh
- Deep Sets（NeurIPS 2017）：https://proceedings.neurips.cc/paper/2017/hash/f22e4747da1aa27e363d86d40ff442fe-Abstract.html

## 4. MFP 宽筛实验

### 4.1 探索过的机制族

- molecule-level BM25；
- raw/IDF overlap；
- Jaccard；
- query coverage、candidate coverage、F2 coverage；
- UniMol mean centroid；
- IDF-weighted UniMol mean；
- IDF-weighted UniMol mean+spread；
- BM25 与 UniMol 全局线性融合；
- BM25 Top-K 内 UniMol 局部重排；
- BM25/UniMol margin 路由；
- BM25 与 UniMol 候选并集。

评价口径：

- 主输出仍是训练集中的具体食物；
- 类别只由评估侧 FlavorDB 映射计算；
- exact-profile 分组五折用于主要 OOF 检查；
- dev 已被历史轮次复用，只作为探索确认，不是独立验证。

### 4.2 单专家 Top-1

| 方法 | exact-profile grouped OOF | dev | 判断 |
|---|---:|---:|---|
| molecule BM25 | 0.375661 | 0.408451（29/71） | 当前最稳主干 |
| UniMol mean+spread | 0.336861 | 0.394366（28/71） | 单独不稳定，但 dev 接近 BM25 |
| OOF 选择线性融合，alpha=-0.125 | 0.398589 | 0.394366（28/71） | OOF 正、dev 负，不作为主输出 |
| 简单 margin route | 0.363316 | 未产生稳定迁移 | 失败 |

UniMol 与 BM25 的 grouped OOF 正误互补：

- 两者都正确：142；
- 只有 BM25 正确：71；
- 只有 UniMol 正确：49；
- 两者都错误：305。

dev 上：两者都正确 25，只有 BM25 正确 4，只有 UniMol 正确 3，两者都错误 39。

结论：结构专家不是更强的全局 Top-1 专家，但存在真实的正交修复样本。简单 margin 无法判断何时应切换，说明“路由信号”仍未解决。

### 4.3 直接融合和局部重排

宽搜索覆盖了全局融合 alpha `[-0.75, 1.25]`、BM25 局部 Top-K `K∈{3,5,10,20,30,50}`、UniMol 权重 `{0.1,0.25,0.5,0.75,1.0}`。

发现：

- grouped OOF 最佳线性融合比 BM25 约 `+0.02293`；
- 但同一 alpha 在 dev 比 BM25 约 `-0.01408`；
- dev 最优 alpha 与 OOF 最优接近，但只有非常窄的权重区间有效；
- Top-K 内局部 UniMol 重排没有超过 dev BM25；
- 单独 Chamfer/双向集合相似度明显较弱。

结论：不把固定加权融合或局部结构重排列为正式主方法。它们可保留为消融，以说明“结构表示需要正确接口”。

### 4.4 最强信号：异质候选并集

| 候选集合 | grouped OOF 类别 oracle | dev 类别 oracle |
|---|---:|---:|
| BM25 Top-3 | 0.594356 | 0.591549（42/71） |
| BM25 Top-3 + UniMol Top-3 | 0.719577 | 0.732394（52/71） |
| BM25 Top-5 | 0.693122 | 0.704225（50/71） |
| **BM25 Top-5 + UniMol Top-2** | **0.754850** | **0.774648（55/71）** |

`BM25 Top-5 + UniMol Top-2` 相对 BM25 Top-5：

- grouped OOF：`+0.061728`，约增加 35/567 个候选覆盖样本；
- dev：`+0.070423`，增加 5/71 个候选覆盖样本。

这是本轮最稳定、最容易解释的 MFP 正信号。它不要求 UniMol 接管排序，也不要求读取候选食品的外部完整画像。UniMol 只从训练食物 profile 中提供与稀疏检索不同的具体食物类比。

注意：oracle 不是可部署成绩。它证明候选池上限提高，下一瓶颈变成如何在约 6–7 个去重候选中选择。

## 5. MFP 的 LLM 方向复核

既有第七轮开放 Scientist：

- 65/71 有效响应；
- 开放候选 exact-food 0；
- 只有 2 个开放食物可由冻结映射识别类别；
- 用开放候选替换 BM25 第三名后，Top-3 类别 oracle 从 0.605634 降到 0.521127。

因此不建议把“无限开放生成”直接加入正式组合。下一次 LLM 实验应利用本轮已经提高的固定候选池：

1. BM25 Top-5 + UniMol Top-2 去重；
2. 对每个具体食物分别生成支持/反对分析，避免候选顺序竞争；
3. Reviewer 只能返回 candidate ID；
4. 候选顺序至少做原序、反序和固定随机序；
5. 不一致时回退 BM25 Top-1；
6. 不允许输出宏类别或新增自由食物。

这种设计把 LLM 权限限制在本轮已证明存在 headroom 的候选选择上。

## 6. MPC 宽筛与组合实验

### 6.1 raw H1+ICL 大候选池

在原始 H1+ICL 并集上比较：

- rank-only；
- rank + candidate-to-partial UniMol mean/max/attention；
- rank + candidate-to-H1 UniMol mean/max；
- full UniMol 条件特征；
- `C∈{0.03,0.1,0.3,1.0}`。

结果：rank-only 基本保持 H1；partial 条件 UniMol 在 OOF 多折为负，dev micro 亦为负；H1-structure 和 full 特征只产生接近零的变化。

结论：历史“raw/global UniMol 无效”得到再次确认。UniMol 不能在未压缩的大候选池里直接承担食品条件排序。

### 6.2 已压缩边界候选池

随后改用第十二轮可复现 rank proposal，与 H1 取并集。这个池已经由合法的 H1/ICL 排名和共识机制压缩，UniMol 只做第二级 residual。

| 方法 | OOF macro hit-rate gain vs H1 | OOF micro hit gain | wins/losses | exact-N |
|---|---:|---:|---:|---:|
| rank-only，C=0.1，全量重排 | +0.013415 | -0.002140 | 116/145 | 568/568 |
| **rank + UniMol，C=0.1，全量重排** | **+0.016284** | **+0.003302** | **120/113** | **568/568** |

UniMol 相对 rank-only 的增量：

- macro 约 `+0.002868`；
- micro 约 `+0.005442`；
- 将 micro 从负方向翻为正；
- 五折 macro gain 均为正：`[0.00538, 0.03230, 0.01154, 0.00964, 0.02255]`。

这说明“候选池压缩”是 UniMol 生效的必要前置条件之一。

### 6.3 exact-N 交换预算

在相同 C=0.1 UniMol scorer 下：

| 最大交换预算 | macro gain | micro gain | wins/losses | 判断 |
|---:|---:|---:|---:|---|
| 1 | -0.003911 | -0.000698 | 65/95 | 失败 |
| 2 | +0.008995 | +0.000093 | 94/94 | 弱信号 |
| 4 | +0.011129 | +0.000279 | 111/120 | 不稳定 |
| 8 | +0.013120 | +0.001093 | 122/127 | macro 正、风险仍高 |
| full compressed-pool rerank | **+0.016284** | **+0.003302** | **120/113** | 最佳无 gate proposal |

“只做一个 UniMol swap”反而失败。正确解释不是 UniMol 应全局接管，而是：当候选池已经由 H1/ICL utility 压缩后，多个相互关联的集合位置需要共同重排；孤立一次交换可能破坏集合内部排序。

### 6.4 选择性 gate

gate 特征只使用推理可得信息：`log(N)`、proposal 交换比例、H1/原 proposal 重合率、候选 cutoff margin、partial/N 比例。

探索结果：

| UniMol proposal + gate | macro gain | micro gain | wins/losses | applied |
|---|---:|---:|---:|---:|
| Cgate=0.01, threshold=0.50 | **+0.016510** | **+0.003791** | 102/90 | 298 |
| Cgate=0.01, threshold=0.55 | +0.016082 | +0.003209 | **78/37** | 192 |

阈值 0.50 的点估计更高；0.55 明显减少负向样本，是推荐的风险控制组合。两者五折都为正。

### 6.5 dev 迁移诊断

将训练侧固定模型迁移到 dev，候选池使用现有 Round-10 proposal：

| 方法 | molecule macro gain vs H1 | molecule micro gain | wins/losses | exact-N |
|---|---:|---:|---:|---:|
| Round-10 proposal | +0.015923 | +0.003047 | 11/4 | 71/71 |
| UniMol rerank | +0.015494 | +0.002476 | 9/3 | 71/71 |
| UniMol rerank + threshold 0.55 gate | +0.015225 | +0.002095 | **8/1** | 71/71 |

缓存覆盖诊断中，三种 proposal 的近似官方 FG-F1 都为 0.657080；但各自仍有 2–4 个唯一分子不在所用缓存中，本轮没有调用 API 补齐。因此这个 FG 数值只能说明“未观察到可见增量”，不能作为完整正式评分。

结论：UniMol 在 OOF 上改善 rank proposal，在 dev 上没有超过现有 Round-10 proposal；但 gate 将 dev 损坏样本由 4 个压到 1 个。故 UniMol-MPC 当前是有依据的**安全/稳健性候选**，尚不是已确认的独立提分主线。

## 7. 本轮失败或不稳定方向

### MFP

- raw UniMol Top-1 全局替换 BM25；
- Chamfer 接管 Top-30；
- BM25 Top-K 内直接 UniMol 重排；
- 固定全局融合权重；
- 仅靠 score margin 在 BM25/UniMol 间路由；
- 无限开放 Scientist 替换检索候选。

### MPC

- raw H1+ICL 大池上的 UniMol 条件排序；
- candidate 与 partial centroid 相似即视为缺失概率；
- 单次 UniMol swap；
- 将 UniMol 作为完整食品需求模型；
- 用 raw FlavorDB functional group 或评估缓存训练 UniMol gate。

这些失败结果不是“UniMol 无效”，而是限定了它的正确接口。

## 8. 建议进入正式实验的组合

这里的“正式实验”指下一阶段按固定代码、固定 prompt、固定配置进行完整运行和消融；不是允许根据正式 test 结果继续调参。

### 8.1 MFP 推荐组合 MFP-U-RV

**MFP-U-RV：Sparse–Structure Union + Restricted Verifier**

1. molecule-level BM25 产生 Top-5 具体训练食物；
2. IDF-weighted UniMol mean+spread 产生 Top-2 具体训练食物；
3. 按 `BM25 1–5 → UniMol 1–2` 去重，保留来源和各自分数，不提供类别；
4. 对每个候选独立生成 evidence-for/evidence-against；
5. 受限 Reviewer 只返回 candidate ID；
6. 三种候选排列做一致性检查；
7. Reviewer 无效或不一致时回退 BM25 Top-1；
8. 最终只输出具体食物。

必须同时运行的消融：

- MFP-C0：修正协议后的原始 Scientist Agent；
- MFP-C1：molecule BM25 Top-1；
- MFP-C2：BM25 Top-5 + Restricted Verifier，不使用 UniMol；
- MFP-C3：BM25 Top-5 + UniMol Top-2 + Restricted Verifier；
- MFP-C4：C3 但不做候选排列一致性门控。

主假设：UniMol 首先提高 candidate recall，Restricted Verifier 将新增 oracle headroom 转化为最终 macro accuracy。

停止条件：如果 C3 的候选 oracle 相对 C2 不再提高，说明重实现错误；如果 oracle 提高但 Reviewer 最终分不提高，则保留候选创新、停止 Reviewer prompt 调参，转向学习型或成对选择器。

### 8.2 MPC 推荐组合 MPC-CU-G

**MPC-CU-G：Consensus Utility + UniMol Residual + Selective Gate**

1. 合法处理字段上的 deterministic H1，始终 exact-N；
2. 有界 ICL/retrieval 补充候选；
3. H1/ICL 共识锁定和 rank-based candidate utility，形成压缩 proposal；
4. 只在 `H1 ∪ compressed proposal` 上使用冻结 UniMol 条件特征；
5. C=0.1 低容量 logistic residual scorer；
6. full compressed-pool exact-N rerank；
7. gate 使用 C=0.01、threshold=0.55；
8. gate 拒绝、结构覆盖不足或任何异常时返回 H1；
9. 确定性执行器去重、排除 partial、补齐并断言 exact-N。

必须同时运行的消融：

- MPC-C0：deterministic H1；
- MPC-C1：H1 + ICL 共识/候选 utility，无 UniMol；
- MPC-C2：C1 + UniMol compressed-pool rerank，无 gate；
- MPC-C3：完整 MPC-CU-G；
- MPC-C4：与 C3 完全相同，但 UniMol 特征置零；
- MPC-C5：C3 的 threshold 0.50 风险—收益对照，仅作预注册消融。

推荐主版本为 threshold 0.55：它不是探索点估计最高者，但 OOF 和 dev 都表现出明显更少的 harmful queries。threshold 0.50 作为预注册的高覆盖消融，不根据正式 test 事后选择。

## 9. 正式阶段指标与判定

### MFP

- 主指标：具体食物输出经官方 judge 映射的 macro accuracy；
- 机制指标：Top-5、union candidate oracle；
- 诊断：exact-food、无效输出、候选顺序敏感度、BM25-only/UniMol-only 修复数；
- 必须逐样本比较 C2 与 C3，确认收益确实来自 UniMol 新候选。

### MPC

- 主指标：官方近似 functional-group macro F1；
- 同报 molecule macro/micro F1；
- 100% exact-N；
- H1、proposal、gate 的 wins/losses/ties；
- UniMol 映射覆盖；
- gate coverage 与 risk；
- 大 N、小 N、partial/N、候选重合率分层。

## 10. 当前最终判断

本轮已经找到可进入完整实验的 UniMol 创新点，但两个任务的角色不同：

- **MFP：UniMol 是异质结构候选召回专家。** 最强信号是 `BM25 Top-5 + UniMol Top-2` 将候选 oracle 在 grouped OOF/dev 同时提高约 6–7 个百分点。
- **MPC：UniMol 是压缩候选池上的任务条件结构残差和安全信号。** 它把 OOF micro 从负转正，并能配合 gate 减少有害查询；但 dev 尚未证明官方指标增量。

因此下一阶段不应实现一个共享的“UniMol fusion weight”。应该实现两个受任务约束、权限完全不同的 UniMol 接口：

```text
MFP: BM25 candidates ─┐
                      ├─ concrete-food union ─ restricted verifier ─ food
UniMol candidates ────┘

MPC: H1 + ICL ─ candidate utility ─ compressed pool
                                      ↓
                              UniMol residual rerank
                                      ↓
                                selective gate
                                      ↓
                              deterministic exact-N
```

这是本轮建议进入正式完整实验的组合设计。
