## 二、不可遗忘的用户要求

### 2.1 任务定义

#### MFP

- 输入：具体分子集合。
- 任务输出：**具体食物名称**。
- 官方主要指标：把预测具体食物映射到宏类别后的 accuracy。
- 辅助诊断：具体食物 Top-1/Top-K 命中、候选召回、候选宏类别 oracle、映射失败和方法合理性。
- 不得直接输出宏类别，也不得先预测宏类别后随意包装一个同类食物。

#### MPC

- 输入：目标食物、partial molecules、缺失数量 `n`。
- 任务输出：**具体缺失分子集合**。
- 官方主要指标：预测分子集合与真实分子集合对应的官能团并集 F1。
- 同时报告：具体分子 Precision、Recall、F1、exact-N、重复、partial 泄漏、映射失败和食品条件合理性。
- 不得直接输出官能团，也不得为了覆盖官能团随意添加载体分子。

### 2.2 优化原则

用户明确要求：

1. MFP 与 MPC 每一轮都要同时进入优化循环，但保持任务、标签、假设、实验和结论相互独立。
2. 每个任务每轮只处理一个最大瓶颈，不做大范围多模块同时修改。
3. 固定循环为：现状核验 → 瓶颈识别 → 第一性原理 → 原始文献 → 单一方向 → 冻结方案 → 用户允许 → 实验 → 审查 → 冻结或停止。
4. 先判断 Scientist 是否给出正确候选，再判断 Reviewer 是否选出正确候选。
5. 同一点连续失败后必须重新定位问题，不得为了救回已投入工作持续调参。
6. 理想目标是官方指标和具体实体恢复同时提高；若难以同时提高，可以官方指标为主，但方法仍必须解决真实任务、合理且可实践，不能服务于评测器投机。
7. 历史高分版本只能取其精华、去其糟粕，不能整版认定为当前最优。
8. 所有新增实验产物尽量使用中文文件名和中文内容。
9. 每轮新操作的授权不得从历史“允许”自动继承。

### 2.3 用户最新纠正

用户指出：

> “不管是MFP还是MPC，虽然之前有最优版本，但是可能在细节上和我们现在的设定有所不同，所以要取其精华、去其糟粕，而不是直接认定为最优。”

并进一步指出 Codex 有遗忘先前工作和中间调整的倾向。后续所有版本比较必须先回答：

- 当时的任务输出是否与当前一致；
- 当时的评测口径是否与当前一致；
- 数据、切分、候选空间和泄漏边界是否一致；
- 提升发生在哪个阶段；
- 哪一模块具有可迁移机制证据；
- 哪些结果只是旧设定、旧代理或完整版本耦合的产物。

## 三、四类版本概念必须分开

### 3.1 历史最高分版本

仅表示某个旧协议下曾取得最高正式数值，例如：

- MFP v9：35/71；
- MPC v2：约 0.6819。

它们不能自动称为当前最优，因为 MFP v9 主要直接预测宏类别，不符合当前具体食物输出；MPC v2 的完整代码和逐阶段机制已不完整，且数据/评测/Agent 设定与当前研究主线存在差异。

### 3.2 最后正式运行版本

- 当前 MFP：v15，23/71。
- 当前 MPC：v12，F1 `0.65386721`。

“最后正式”只表示磁盘上最后一次被冻结的正式产物，不表示性能最好，也不表示当前源码的全部研究逻辑。

### 3.3 当前研究源码

当前 `optimized_agent.py` 和 runner 标识为 `optimized_agent_v15_mfp_concrete_protocol`。其中包含：

- 当前 MFP 具体食物协议；
- MPC v14/v15 相关实现与 disabled policy；
- 尚未接入正式推理的 v16 Scientist builder。

源码存在不等于模块已经准入。

### 3.4 当前设定下已验证的冻结主干

这不是某个完整历史版本号，而是经过当前任务定义重新核验后允许作为控制的机制集合。当前只能谨慎表述为：

- MFP：具体食物输出、BM25 类比候选可作控制；开放 Scientist 尚未通过；Reviewer 暂无执行增益准入。
- MPC：H1/KEEP_H1、exact-N、去重、排除 partial、有限局部动作和零预算回退具有稳定机制依据；具体 H1 实现仍需在当前设定下重新做版本化对照，不能直接等同于 v2、v7、v9、v12 或当前 v15 源码中的任一完整版本。

## 五、当前问题与下一轮方向边界

### 5.1 MFP 当前问题

Scientist 候选空间是主要矛盾：

- 训练食物和 dev 食物零交集；
- 封闭训练候选使具体食物召回必为 0；
- 字符串证据桥覆盖低且噪声大；
- Reviewer 没有正确候选时无法补救。

第七轮已经实际验证：

- `scripts/第五轮_MFP_开放具体食物科学家候选验证.py`
- 71 条 dev 均完成一次开放 Scientist 调用；
- 65 条响应有效，但具体食物命中仍为 0；
- 宏类别 Top3 oracle 从 `0.60563` 降至 `0.52113`；
- 已触发停止条件，不得继续调同一提示或接 Reviewer。

### 5.2 MPC 当前问题

不能简单表述为“v12 后都失败，所以继续用 v12”。更准确的是：

- v13–v16 各自证明了目标对齐、Action Bank、搜索扩展或场景覆盖的局部信号；
- 但没有一版完成当前协议下 Scientist → Reviewer → Executor 的完整准入；
- 因而正式产物有意停留在 v12；
- 这只是一项版本冻结事实，不证明 v12 是当前最优，也不证明当前 v15 源码已经获得正式成绩。

第七轮已经补齐当前 pairwise occurrence H1 在 MPC dev 的官方口径 control：71/71 exact-N，具体分子 F1 `0.69412`，数据库对称官能团 F1 `0.91261`，官方非对称官能团 F1 `0.64910`。后两者的配对差值为 `-0.26351`，95% bootstrap 区间完全为负。

下一次 MPC 不应直接重跑 v2/v9，也不应继续调 v14–v16 的同类 DB proxy 门控。当前更具体的问题是：H1 高频选择 `thiamine`、`methanethiol`、`vanillin` 等扩大预测官能团并集的重复分子，官方 precision 只有 `0.59337`。下一轮只能设计一个训练内、分子内禀、对齐官方 53 项词表且不读取 dev/正式 cache 的查询条件化 precision 控制机制；Reviewer 继续冻结。这只是候选方向，尚未获准实施。

- `Associated Foods` 对低频分子有关系栏目 `2/10`、对高频分子有关系栏目 `9/10`，但 JSON 只返回 FooDB 外部表指针和来源链接，不返回具体食物，因此 MFP 与 MPC 的训练食物直接关系命中均为 `0/20`；
- 在剩余额度内固定访问 5 个低频、5 个高频 FooDB 公共 compound 页面，页面均可读取且均存在 `Associated Foods` 栏目，但对应训练食物仅命中 `1/10`：低频 `1/5`，高频 `0/5`；
- 全阶段共发出 80 次 HTTP 请求，已达到预先冻结上限并停止；未根据中途结果改样本或扩大来源。

### 审查结论

- 结论类型：**获得局部信号但暂不准入**；
- PubChem 的栏目覆盖不能当作直接关系覆盖；它只是把 FooDB 标识暴露为外部表，无法直接给 MFP Scientist 生成具体食物，也无法给 MPC Reviewer 验证具体 food—molecule 对；
- FooDB 公共 HTML 的直接关系覆盖只有边界值 `10%`，且高频层为 `0%`；同时 PubChem 此栏目本身明确溯源到 FooDB，不能把两者算作两个独立来源；
- 该证据不足以进入 dev，也不足以实施“替换 MFP 第三候选”或“MPC H1 边界交换”；两边当前模型和 Reviewer 均继续冻结；
- 不继续在 PubChem 标题、同义词或网页解析细节上反复调参。下一次若仍尝试关系证据，应更换为独立文献关系抽取数据（如 FoodChem 方法及其公开语料），并先做一次严格有上限的许可、数据可得性与训练侧覆盖审计；若仍低覆盖，则离开外部关系知识路线并重新定位 Scientist。

### 审查边界

- 本阶段仅做只读数据/代码/历史审查和公开论文核验；未修改模型代码、未运行实验、未调用 DeepSeek、未读取正式 test 逐样本、未扩展数据；

### MFP：第一性原理因果链

1. 当前任务输出是具体食物实体。正确实体未进入 Scientist 候选时，Reviewer 无论怎样选择都不可能恢复它，因此第二轮 `0.605634` 的宏类别候选 oracle 不能替代 exact-food 候选召回；
2. 71 条 dev 只有 53 个唯一输入分子谱，完全相同输入至少造成 18 个具体食物错误不可避免；新方法只能改善其余可辨识部分，不能宣称解决整个实体恢复问题；
3. 第七轮具体食物 Top3 召回为 0，且生成理由主要依赖通用风味分子，说明当前可行动失败发生在 Scientist 的搜索起点，而不是候选选择；
4. FoodPuzzle 原文的 MFP 初始化明确从训练频率计算信息量/熵，并选择最多 10 个低熵分子作为搜索起点；其错误分析还把“以 thiamine、betaine 等通用分子初始化，而不是 hydrogen sulfide、diethyl sulfide 等诊断分子初始化”列为最大错误类型（32%）；
5. TACL 2024 *Lost in the Middle* 证明长上下文中相关信息的位置与无关内容会显著影响模型使用证据的能力。这支持缩短平铺分子列表、突出诊断起点，但不证明任意 Top-K、IDF 或近邻对比公式；
6. ICML 2018 attention-based deep multiple instance learning 与 ICML 2019 Set Transformer 表明，集合任务中元素重要性和元素交互原则上应由任务监督学习并保持置换不变。当前 MFP 的 exact-food 标签 train/dev 零交集且样本很小，不足以可靠训练新的实体级集合注意力，因此本轮不新增一套 learned sketch 网络。

### MFP：方案取舍

- **否决**此前自拟的“Top12 train document frequency + 近邻对比”公式：它没有被顶级论文直接支持，也同时改变 K、稀有度定义和近邻对比三个因素，无法形成清晰归因；
- **保留为下一轮最小方法校正**：严格复核并复现 FoodPuzzle 官方“最多 10 个低熵/高诊断性起始分子”，只替换开放 Scientist 的输入起点，Reviewer、BM25 前二候选、生成模型、输出规范和合法性检查全部冻结；
- 这不是新颖性主张，而是先判断当前失败是否来自没有忠实实现原论文的搜索初始化。若 train-only/开发诊断中具体食物 Top3 召回仍为 0，则停止继续调整相同开放提示词；
- GENRE（ICLR 2021）的目录约束生成可以保证输出落在已有实体目录中，且 71 个 dev Gold 名称全部已存在于当前 `food_entities` 目录，但它只能解决名称合法性，不能证明语义正确性；当前纯词法目录重排的 Gold Top3 只有 `2/71`，因此不与本轮起点校正同时加入，只作为后续独立候选方向。

### MPC：第一性原理因果链

1. MPC 是给定查询后从有限分子宇宙中选出 exact-N 个标签，本质是查询条件化的多标签排序；
2. 训练候选宇宙已覆盖 dev Gold 的 `5210/5251=99.2192%`，H1 的 1187 个漏召回中有 1146 个已在宇宙内，因此最大问题不是候选供给，而是查询内排序；
3. 当前 H1 每个训练查询随机最多保留 20 个正分子。训练中的 42,981 个正样本 occurrence 实际只保留 9,351 个（21.76%），1,596 个唯一正分子中有 620 个从未作为正样本参与训练；
4. 这些“零正监督”分子在 dev Gold 中出现 145 次，H1 只命中 3 次（2.07%）；其余 Gold 命中 `4062/5106=79.55%`。这不是因果证明，但失败与监督缺口高度同向；
5. ICML 2008 ListMLE 说明排序应把查询内列表作为训练单位；JMLR 2014 的 F-measure 研究说明 F1 是不可分解结构指标，替代损失可能具有高 regret；NeurIPS 2015 SLEEC、NeurIPS 2019 AttentionXML、NeurIPS 2023 长尾极端多标签研究共同指出稀有标签监督是多标签检索的核心难点；
6. 上述文献支持“查询级、长尾感知、最终需按 F1 审查”，但不要求本轮立刻把模型换成 ListMLE。历史上已有查询条件 pairwise/listwise Reviewer 和 action-bank 失败；大改目标函数会把“补齐正监督”与“替换排序器”混为一谈。

### MPC：保留的最小因果干预

- 只删除 `_fit_rankers` 中对正样本的随机 `[:20]` 截断，保留每个训练查询的全部真实正分子；
- 仍使用同一个 H1 pairwise 模型、同一特征、同一未标注/困难负样本、同一候选宇宙和 exact-N；每个查询总权重继续归一，避免大标签集合仅因 pair 数量更多而支配训练；
- 先做 train-only 的 exact-profile-cluster grouped OOF，具体分子 F1 是主任务诊断，数据库官能团 F1 作为辅助安全指标；不使用 dev/正式 cache 选择方案；
- 准入要求预先固定：具体分子 F1 的配对 bootstrap 95% 下界大于 0、官能团 F1 不下降且多数折非负。失败即停止，不转为同轮调参或追加 Reviewer。

### 第一性原理与文献边界

- MFP 的新归纳偏置是“同宏类别的分子集合在可学习度量中接近”，而不是新增外部知识。Deep Sets 支持集合表示必须保持置换不变；Supervised Contrastive Learning 支持用同标签拉近、异标签推远来学习度量。两者都不保证恢复未见具体实体，因此具体食物命中只诚实报告，不宣称已解决实体辨识；

历史与文献核验表明，MFP 缺失的不是另一种 molecule↔molecule 相似度，而是 molecule structure↔open food name 的 grounding：

- GROVER（NeurIPS 2020）用大规模无标签分子预训练 2D 图表示，但没有文本/食物名称通道，不能直接补足当前缺口：https://papers.nips.cc/paper/2020/hash/94aef38441efa3380a3bed3faf1f9d5d-Abstract.html

- 官方代码和 checkpoint 可获得，但依赖较旧的 Python/PyTorch/MegaMolBART 或图模型环境，存在真实工程风险：https://github.com/chao1224/MoleculeSTM
- 3D-MoLM（ICLR 2024）使用 UniMol、Q-Former 和语言模型建立 3D molecule-text bridge，证明结构—文本投影需要专门对齐，而不是直接把 UniMol cosine 当语义证据；但其生成系统更复杂，本轮不优先采用：https://proceedings.iclr.cc/paper_files/paper/2024/hash/4af24e6ce753c181e703f3f0be3b5e20-Abstract-Conference.html

### 第一性原理与文献适配

- MFP 正确输出是可组合的自然语言实体名，而不是训练实体 ID。GENRE（ICLR 2021）证明自回归生成实体名称可直接建模上下文—名称关系；T5（JMLR 2020）支持把下游任务统一成 text-to-text 适配；LoRA（ICLR 2022）支持冻结底座、只学习低秩任务增量。可借鉴的是开放名称生成和参数高效适配，不能照搬 GENRE 的 Wikipedia 实体目录或受限解码，因为本项目没有合法的完整食物目录：
  - https://openreview.net/forum?id=5k8F6UU39V
  - https://jmlr.org/papers/v21/20-074.html
  - https://openreview.net/forum?id=nZeVKeeFYf9
- MPC 的 query 与候选需要联合条件判断。BLINK（EMNLP 2020）显示 cross-encoder 通过拼接上下文和候选文本可以改善零样本候选重排；本项目只借鉴“联合编码后评分”，不引入其知识库描述、实体目录或外部负例。训练监督仍只是真实缺失分子：
  - https://aclanthology.org/2020.emnlp-main.519/
- Qwen 官方 model card 声明该模型是 0.5B decoder-only 预训练语言模型并支持 32K context；本地长度核验显示 MFP 90%/95% 输入约为 1166/1398 token，仅 2/567 超过 2048；MPC 候选前缀最大约 346 token。因此固定 2048/512 上下文具有工程可行性，但 MFP 两条超长输入会按冻结规则截断并记录：
  - https://huggingface.co/Qwen/Qwen1.5-0.5B-Chat

### MFP 冻结实验：开放具体食物 Scientist 的任务适配

- 唯一变化：以冻结 Qwen 底座加独立 LoRA adapter，把排序后的任务内分子名称集合直接生成为具体食物名称；不接 BM25 候选、不接 Reviewer、不接 UniMol、不提供宏类别；
